TENIX Oneทดลองใช้งานเดโม

TENIX One — Security Operations Platform

เอกสารแนะนำโครงการสำหรับผู้บริหารและ Hiring Manager

1. ชื่อและวัตถุประสงค์

TENIX One คือแพลตฟอร์ม Security Operations (SOC) แบบรวมศูนย์ สำหรับทีมที่ต้องเฝ้าระวังภัยคุกคามและดูแลโครงสร้างพื้นฐานของหลายองค์กรพร้อมกัน ระบบรวมข้อมูลจากเครื่องมือด้านความปลอดภัยหลายประเภทไว้ในหน้าจอเดียว เพื่อให้นักวิเคราะห์ตรวจสอบเหตุการณ์ ตัดสินใจ และตอบสนองได้เร็วขึ้น โดยไม่ต้องสลับหลายคอนโซล

2. ภาพรวมความสามารถ

กลุ่ม ความสามารถ
Detection & Response รวม alert จาก Endpoint, SaaS, Network และ Identity จัดลำดับตามความรุนแรง มอบหมายผู้รับผิดชอบ ปิดเคส และเก็บประวัติ
Exposure Monitoring เฝ้าระวังบัญชีและรหัสผ่านที่รั่วไหล โดเมนเลียนแบบ แยกตามโฟลเดอร์ลูกค้า พร้อมรายงาน A4
Web & Edge Security ภาพรวม WAF ความปลอดภัยของแต่ละ Zone การบล็อก IP และตรวจจับการแก้ไขเนื้อหาเว็บโดยไม่ได้รับอนุญาต
Infrastructure Monitoring สถานะเครื่องและ agent, การค้นหาอุปกรณ์ในเครือข่าย, การตรวจสอบว่าบริการยังทำงานอยู่
Operations Console SOC Wall สำหรับห้องปฏิบัติการ แสดงเหตุการณ์สดแบบเต็มจอ
Management หลาย Tenant, ผู้ใช้และสิทธิ์ 3 ระดับ, API token แบบอ่านอย่างเดียวสำหรับลูกค้า, ควบคุมสิทธิ์ส่วนขยายเบราว์เซอร์, audit log

3. ฟังก์ชันหลักและคำอธิบาย

โมดูล คำอธิบาย
Dashboard ตัวชี้วัดหลัก (alert ที่เปิดอยู่, critical, ปิดเคสต่อสัปดาห์) แนวโน้มรายวันแยกตามความรุนแรง เครื่องและ MITRE technique ที่พบบ่อย และสถานะการเชื่อมต่อกับระบบภายนอก
Alerts ตารางที่กรอง ค้นหา และเรียงได้ ดำเนินการเป็นกลุ่ม (รับเรื่อง/ปิดเคส) ลิ้นชักรายละเอียด 4 แท็บ: รายละเอียด, ไทม์ไลน์, Raw log (JSON ต้นฉบับ), บันทึกของทีม
Email Monitoring ภาพรวมการรั่วไหลรายเดือน บัญชีที่รั่วพร้อมสถานะเคส การเปิดเผยรหัสผ่านโดยบันทึกการเข้าถึง การแจ้งเจ้าของบัญชี บังคับเปลี่ยนรหัสผ่าน โดเมนเลียนแบบ และโฟลเดอร์ลูกค้าที่ออกรายงาน A4 ได้
SOC Wall หน้าจอเต็มสำหรับห้อง SOC ตัวเลขสำคัญ เหตุการณ์สด และกำหนดระดับความรุนแรงต่ำสุดที่แสดง
Web Defacement เทียบเนื้อหาหน้าเว็บกับค่าอ้างอิง (baseline) แสดงสถานะ 4 ระดับ ความแตกต่างเป็นบรรทัด และตั้ง baseline ใหม่ได้
Cloudflare WAF Insights (คำขอ บล็อก ประเทศ เส้นทาง กฎ), ความปลอดภัยของ Zone (คะแนนและคำแนะนำ), กฎและรายการ IP ที่ถูกบล็อก
System Health สถานะเครื่องและ agent, กราฟทรัพยากร, เทอร์มินัลแบบจำกัดคำสั่งที่บันทึกทุกการใช้งาน, อัปเกรด agent
Network Monitor รายการอุปกรณ์ที่ค้นพบ สแกนพอร์ต แผนผังเครือข่าย และการค้นหาอุปกรณ์รอบใหม่
Uptime Pulse (TUP) ตรวจบริการผ่าน HTTPS หรือผ่าน agent ขนาดเบา ประวัติเหตุการณ์ และการตั้งค่าการแจ้งเตือนที่แยกจากระบบ alert ความปลอดภัย
Dump IOC นำเข้ารายการ IOC ตรวจรูปแบบ ตัดรายการซ้ำ แบ่งเป็นชุด และสร้างสคริปต์
Tenants จัดการองค์กรลูกค้า การแจ้งเตือนต่อ Tenant การเชื่อมต่อระบบภายนอก และการแสดงบน SOC Wall
Users ผู้ใช้ เมทริกซ์สิทธิ์ตามบทบาท คำเชิญที่จำกัดตามระดับของผู้เชิญ และการป้องกันการลบ Super Admin คนสุดท้าย
Proxy Hub ออก token แบบอ่านอย่างเดียวผูกกับ Tenant เดียว แสดงค่า token เพียงครั้งเดียว
Tenix FullSnap ควบคุมผู้ที่ใช้ส่วนขยายเบราว์เซอร์ ยืนยันตัวตนด้วย OTP ทางอีเมล จัดกลุ่มตามแผนก และดูอุปกรณ์ที่ล็อกอินอยู่
Audit log บันทึกการดำเนินการสำคัญทั้งหมดพร้อมผู้ดำเนินการและเวลา

4. ขั้นตอนการทำงานของผู้ใช้

จัดการ alert: เข้าสู่ระบบด้วยรหัสผ่านและ MFA → เปิด Dashboard ดู alert ที่ต้องดำเนินการก่อน → เปิดหน้า Alerts กรองตามความรุนแรง → เปิดรายละเอียด ตรวจ Raw log → รับเรื่องและมอบหมาย → บันทึกข้อสังเกต → ปิดเคส ทุกขั้นถูกบันทึกใน audit log

ตอบสนองกรณีบัญชีรั่วไหล: พบบัญชีใน Email Monitoring → เปิดรายละเอียดดูแหล่งที่พบ → เปิดเผยรหัสผ่านเมื่อจำเป็น (บันทึกการเข้าถึง) → แจ้งเจ้าของบัญชี → บังคับเปลี่ยนรหัสผ่าน → เปลี่ยนสถานะเคสเป็น "แก้ไขแล้ว"

เตรียมข้อมูลให้ลูกค้า: สร้างโฟลเดอร์ลูกค้าและกำหนดสิ่งที่เฝ้าระวัง → ตรวจสอบผลที่พบ → ออกรายงาน A4 (พิมพ์หรือบันทึกเป็น PDF)

เริ่มต้นใช้งานกับลูกค้าใหม่: สร้าง Tenant → ตั้งค่าการเชื่อมต่อ → เลือกระดับ alert ที่จะแจ้งเตือน → ออก API token แบบอ่านอย่างเดียวให้ระบบของลูกค้า

5. กลุ่มผู้ใช้งานและสิทธิ์

บทบาท สิทธิ์โดยสรุป
Super Admin ทุกความสามารถ รวมถึงจัดการ Tenant ผู้ใช้ สิทธิ์ และดูข้อมูลอ่อนไหวโดยมีการบันทึก
Staff ตรวจสอบและตอบสนองต่อ alert มอบหมายงาน ส่งออกรายงาน แต่จัดการผู้ใช้ไม่ได้
Intern ดู Dashboard และ alert อย่างเดียว ไม่สามารถเปลี่ยนแปลงข้อมูล

บทบาททั้งสามเรียงเป็นบันได โดยบทบาทที่สูงกว่ามีสิทธิ์ครอบคลุมบทบาทที่ต่ำกว่า สิทธิ์แบ่งเป็นความสามารถย่อย (เช่น ตอบสนอง, จัดการผู้ใช้, ดูข้อมูลอ่อนไหว) การเชิญผู้ใช้ใหม่ทำได้ถึงบทบาทเท่ากับของผู้เชิญเท่านั้น

7. แนวทางการออกแบบสถาปัตยกรรม

  • แยกหน้าที่ของข้อมูล: ข้อมูลที่ต้องถูกต้องและมีความสัมพันธ์ (ผู้ใช้ Tenant การตั้งค่า) อยู่ใน PostgreSQL ส่วน log ปริมาณมากอยู่ใน ClickHouse
  • ตรวจสิทธิ์ที่ฝั่ง API เสมอ: การซ่อนปุ่มในหน้าเว็บไม่ใช่มาตรการป้องกัน ทุกเส้นทางที่เปลี่ยนแปลงข้อมูลผ่านการตรวจสิทธิ์ตามความสามารถของบทบาท
  • แยกข้อมูลตาม Tenant และแยก token ของลูกค้าเป็นแบบอ่านอย่างเดียวผูกกับ Tenant เดียว
  • หลักการข้อมูลอ่อนไหว: รหัสผ่านที่รั่วไหลไม่ถูกเก็บในฐานข้อมูล การเปิดเผยทุกครั้งถูกบันทึก secret ของการเชื่อมต่อเก็บแบบเข้ารหัสฝั่งเซิร์ฟเวอร์
  • ระบบย่อยที่มีขอบเขตของตัวเอง เช่น การแจ้งเตือนการหยุดทำงานของบริการแยกจากการแจ้งเตือน alert ความปลอดภัย เพื่อไม่ให้ตั้งค่าปนกัน

8. ประโยชน์ของระบบและปัญหาที่ออกแบบมาเพื่อแก้ไข

ปัญหา สิ่งที่ระบบช่วย
เครื่องมือกระจัดกระจาย ทีมต้องสลับหลายคอนโซล รวม alert, การรั่วไหล, WAF และสถานะระบบไว้ในที่เดียว
ดูแลหลายองค์กร ข้อมูลและสิทธิ์ปนกัน แยก Tenant ชัดเจน กำหนดสิทธิ์ตามบทบาท และบันทึกการใช้งาน
ลูกค้าต้องการข้อมูลของตนเองโดยไม่เข้าถึงข้อมูลอื่น API token แบบอ่านอย่างเดียวผูกกับ Tenant และรายงานแยกตามลูกค้า
ใช้เวลาตรวจสอบเหตุการณ์นาน จัดลำดับตามความรุนแรง ลิ้นชักรายละเอียดพร้อม Raw log และไทม์ไลน์
ข้อมูลอ่อนไหวถูกเปิดดูโดยไม่มีหลักฐาน การเปิดเผยแต่ละครั้งบันทึกใน audit log

9. บทบาทและความรับผิดชอบของผู้พัฒนา

ผู้พัฒนาดูแลระบบแบบ Full-stack ตลอดวงจรงาน ได้แก่

  • ออกแบบและพัฒนาส่วนติดต่อผู้ใช้ (Next.js / TypeScript) รวมถึงการรองรับหลายขนาดจอและธีมสว่าง/มืด
  • พัฒนา API และตรรกะธุรกิจ (Express / TypeScript) พร้อมระบบสิทธิ์ตามบทบาทและการบันทึกการใช้งาน
  • ออกแบบโครงสร้างฐานข้อมูลและเลือกที่เก็บข้อมูลให้เหมาะกับลักษณะข้อมูล
  • เชื่อมต่อกับระบบภายนอกด้านความปลอดภัย (endpoint, edge, อีเมล, เครือข่าย)
  • ติดตั้งใช้งานและดูแลระบบบนเซิร์ฟเวอร์ รวมถึงการตั้งค่า reverse proxy และการเฝ้าสังเกตการทำงาน

ขนาดของโครงการ: โค้ด TypeScript ประมาณ 66,000 บรรทัด ประวัติการพัฒนา 57 commits ระหว่างวันที่ 9 มิถุนายน – 15 ตุลาคม 2026

การเชื่อมต่อกับระบบภายนอก (ทดสอบการเชื่อมต่อ, แจ้งเจ้าของบัญชี, บังคับเปลี่ยนรหัสผ่าน) จำลองการเรียกและผลตอบกลับ
การดูระบบในฐานะบทบาทต่างๆ และเมทริกซ์สิทธิ์ 10 รายการ ตัวเลือกและตัวอย่างสำหรับสาธิตผลของสิทธิ์ ไม่ได้สะท้อนรายการสิทธิ์จริงของระบบ
